# Apple Music 1606 平板顶栏阴影淡入淡出

## 视频与代码证据

用户提供的视频为 1024×720、30fps、约 2.75 秒。截取顶部并检查抽屉打开过程：约 1 秒处，顶栏文字仍逐步变透明，胶囊外部阴影已经突然消失；关闭抽屉时阴影也突然恢复。它不是一层始终残留的阴影。

原来的 `FragmentTabletGlassSession` 把导航透明度写到 `GlassHostView.alpha`。这个外层 View 的边界等于原生顶栏的布局/点击边界；内部 Compose 绘制区域则向外扩展，容纳胶囊阴影。父层处于分数透明度时，合成边界会截掉边界之外的绘制，符合视频中阴影先消失、后突然出现的现象。这里记录的是视频结合绘制结构得到的诊断，尚未在设备上验证修补后的表现。

## 修补

- 在 `glass` 模块的 `GlassHostView` 增加可选的 `contentAlpha`，只调整包含留白的内部 Compose 层，外部点击边界保持不变。
- 仅 7.0 平板顶部导航使用这个透明度入口；初始透明度和点击判定也读取同一个入口，避免不可见顶栏继续接收点击。
- 顶栏阴影留白从 32dp 增至 64dp。默认阴影半径 24dp，其绘制区域外扩 48dp，另有 4dp 纵向偏移；64dp 覆盖这部分绘制范围。
- 透明度继续来自原生导航状态和原来的播放器展开曲线，不增加独立动画或延迟。
- mini、手机和旧版会话保留原有绘制路径；不修改 native profile、配置、双栏、歌词、队列、封面布局或原生封面动画。
