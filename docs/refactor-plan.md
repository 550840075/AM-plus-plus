# AM++ 版本适配重构

2026-10-02；基线 `97c4b69`（AM++ 1.6.2）。本设计经用户确认实施。

## 目标与边界

集中版本资料、隔离宿主接入、逐项迁移功能。保留 Apple Music 6.5.1/1583、6.5.2/1586、6.5.3/1599 的现有行为及已知降级；6.5.0 仅保留参考资料。7.x 建立接入接口和夹具，正式包重新取证并验收前不启用。操作表元数据、主页封面连续性两处已知降级独立修复，不与结构迁移混合。

不改变配置 schema 15、偏好键、默认值、宿主私有目录、文件 ID、迁移 marker、ZIP 格式、SQLite 名称或缓存命名空间。不升级依赖或编译工具链。不增加桌面入口、权限或全局目录语言功能。

## 模块与依赖

| 模块 | 职责 | 依赖 |
|---|---|---|
| app | APK、HookEntry、装配、功能编排、设置 UI、Android 存储/文件实现 | core、host-api、hook-runtime、host-applemusic、glass |
| core | 纯模型/配置编码、歌词事务/转换、网络、缓存/并发与布局策略 | JVM/Kotlin 库 |
| host-api | 语义宿主能力、事件、安装结果和订阅 | core |
| hook-runtime | libxposed 注册、回调失活、作用域与日志 | core |
| host-applemusic | profile、符号/资源解析、DexKit、反射与版本接入 | core、host-api、hook-runtime |
| glass | 模块自己的 Compose、材质、动画与渲染 | core、backdrop |
| backdrop | 固定上游及已声明补丁 | 当前依赖 |

先保留包名。只公开跨模块需要的契约。core 无 Android/Xposed/反射/渲染依赖，宿主模块不依赖 app/glass。公开语义 API 不暴露 Method/Field、混淆名或宿主 AndroidX/Compose 类型，框架 View 可以跨边界。

能力覆盖当前歌曲、播放器/双栏/导航/mini、歌词/原生 TTML、目录查询、元数据展示、设置入口/文件结果、蜂窝、Editorial Video、DPI。通过配置、资产、调度器和业务/呈现回调注入，原生指针使用不透明句柄。

## 版本资料与生命周期

每个精确 tuple 一份随模块打包的 JSON profile，包含页面架构族、资格、目标与完整描述符、成员/资源、契约标识、候选顺序/策略、已验证改名、缺失/降级及证据。运行时和 Python 读取同源数据。契约仍用 Kotlin；两套解析引擎保留为内部实现，迁移不改变旧解析顺序或回退规则。旧首匹配例外显式登记，新目标歧义拒绝。显示字符串不用于资格判断，渲染器不保存宿主白名单。

安装顺序保持版本确认 → 配置迁移/绑定 → DPI → 早期资源 → Application 后能力 → 设置入口。资源基础失败保持原传播；局部符号缺失只降级局部能力。先解析，再注册，再发布句柄；安装失败使回调失活，关闭会话清理监听/任务/视图和模块拥有的状态，不依赖可靠 unhook。安装和异步就绪分开报告。

## 阶段与验收

| 阶段 | 工作 | 门槛 |
|---|---|---|
| P0 | 设计、功能矩阵、profile/格式/测试基线 | 每项有保全项、已知降级独立登记 |
| P1 | 新模块，纯代码/网络/Hook 提取 | 原测试保留，无循环依赖 |
| P2 | 统一 JSON、资格/改名/校验 | 旧资料/顺序/资格与基线一致 |
| P3 | 分离能力与工厂，服务注入/注册作用域 | 假宿主可测，宿主可独立编译 |
| P4 | 身份/字体/蜂窝/Editorial → 歌词 → 双栏/玻璃 → 元数据 | 逐项测试和旧行为核对，单条活动路径 |
| P5 | 设置入口、SAF、页面、状态、控制器分离 | 草稿/显隐/所有操作保留 |
| P6 | 新架构族、Fragment 生命周期、beta 夹具/模板 | 生产不放行 1606/未知正式版 |
| P7 | 两处降级分别取证/修复 | 独立测试/证据/真机结果，缺口明确 |
| P8 | 文档、CI、全量检查和 APK | 无新增退化，所有未验证项明确 |

每阶段独立提交，移动/提取与行为修复分开。出现退化先恢复对应阶段。格式不变，回滚无需反向数据迁移。

双栏/玻璃分离宿主状态/事务、视图挂载/恢复、歌词/封面布局、导航/mini 事件与模块呈现。绑定时缓存成员/资源/视图；滑动/透明度/高亮/绘制不得扫描 DEX、解析反射或执行磁盘/网络。元数据分离宿主目录访问、调度、地区策略、持久缓存与各展示表面，保持主线程/后台边界、优先级、批量限制、缓存隔离和原名证据。

## 验证与交付

基线 app 810 + glass 14 项测试通过，上游参考哈希通过。迁移保留旧测试；路径断言改为新职责或行为断言，Manifest/入口/依赖限制保持检查。

新增：精确版本/错 tuple/未知版；错签名/同名异义/继承/歧义/改名/ClassLoader；失败失活/幂等/发布顺序/销毁重建；歌曲 generation/手动优先/禁用 ID/指针失效/网络失败；旧格式与资产读写；旧 Activity/新 Fragment 同契约；依赖边界。Python 读 profile，检查 APK/XAPK/APKS/splits、符号描述符和资源入口；静态不能证明的行为明确记录。

CI：全模块测试、架构/profile 校验、app/glass Lint、APK 和上游哈希。三个旧 tuple 分别真机验收，保留截图/录屏/模块日志，既有降级与新增退化分别统计。相同设备/设置/场景至少五次对照启动及帧时间，持续超过基线 10% 的退化需解决；监听/任务/session 不得随重建累积。设备或旧包缺失时记录待验收，不将静态/JVM PASS 当真机通过。

后续普通混淆变更只更新 profile 和证据；页面架构变更集中于新宿主接入，设置、歌词服务和渲染核心可保持。
