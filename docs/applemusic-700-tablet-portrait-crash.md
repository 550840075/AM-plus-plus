# 1606 平板横屏切竖屏崩溃修复

## 现场与原因

2026-10-03，在已连接的 OPD2413 / Android 16 平板上读取崩溃并复现：暂停、mini 收起时，横屏转竖屏也会退出。设备原模块为已验收 v12（1.6.2/112，SHA-256 `e21c3c89c11e3990aed2bff3e6c2f251659c56317641ac9375b6a19e07c7b4ba`）；该旋转路径与合并后的 1.6.3 相同。

13:42:48 的 PID 5001 报 `IllegalArgumentException: mKaraokeLineEffectiveWidth not yet initialized!`，路径为原生 `A.n0 → b0 → k → l → RecyclerView.onLayout`。它与玻璃渲染无关，是模块右侧歌词的恢复/测量时序冲突。

旋转重建时，Android 必须先找到保存的右侧 Fragment 容器，再由模块提交移除事务，恢复竖屏原生播放器。此前容器初始宽度为 1px，正式栏宽在 `onSizeChanged` 中设置；这个回调晚于子视图测量，新的布局参数只会安排下一次测量。第一轮歌词绑定已经使用 1px，原生有效宽度减去内部 padding 后不能满足正数要求。临时诊断记录明确显示 `owns=true viewport=1 root=1 orientation=1`。

另外，竖屏原来的右栏计算为 `width - fullWidth - margins`，最终仍被限制成 1px；旧缓存行宽度修补又受横屏条件限制。只放开条件/调整公式仍不足以解决第一轮测量，已通过现场失败复验排除这种不完整修补。

## 实现

- 在 wrapper 的 `onMeasure` 中先设置左右栏宽，再测量子视图。仅参数变化时更新 LayoutParams，避免重复请求整棵原生树布局。
- 横屏继续使用原来的半宽栏位；竖屏恢复中的临时右容器使用可测量的全宽，直到 Fragment 移除完成。它不作为竖屏双栏展示。
- 已归属模块右侧 Fragment 的缓存行宽度初始化持续到 `onDestroyView`，不因旋转时资源方向先变成竖屏而停止。
- 双栏启用条件仍仅横屏；竖屏为原生单栏，回横屏再启用双栏。玻璃启用条件、原生封面动画、配置格式和其他模块均未改变。
- 临时身份/测量诊断日志从最终源码删除。

## 验证

新增两个 JVM 回归：竖屏恢复期间的临时右栏仍能满足原生有效宽度公式；横屏普通和奇数宽度保持原来的分栏几何。全模块合计 986 项测试通过，失败/错误/跳过均为 0；app/host-applemusic Debug Lint、Release vital Lint 和 Release 构建通过。架构、冻结 profile、渲染参考及 262 项原包契约检查通过，未变化任务部分使用已有 Gradle 结果。

修补后诊断候选的 PID 11350 保持存活：mini 暂停状态横屏转竖屏通过；展开播放器暂停、播放各两轮横竖屏往返通过。截图确认竖屏原生单栏、横屏左侧 SONG/右侧歌词，以及竖屏 mini 玻璃均保留。测试结束恢复原来的暂停状态和系统旋转设置。这些结果仅覆盖本次旋转崩溃，不代表完整功能/性能矩阵已完成。
